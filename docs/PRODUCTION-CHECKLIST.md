# قائمة تحقق ما قبل الإنتاج

هذه القائمة لا تعني أن البنود منجزة؛ علّم كل بند بعد وجود دليل اختبار أو إعداد موثق.

## الأمن والخصوصية

- [ ] تدوير أي أسرار ظهرت في ملفات أو محادثات أو سجلات، والتأكد أن `.env` خارج التحكم بالمصدر.
- [ ] استخدام HTTPS، ومراجعة CORS والكوكيز والجلسات، وتحديد معدل الطلبات.
- [ ] مراجعة مخاطر XSS لأن رمز Bearer مخزن في `sessionStorage` في البنية الحالية.
- [ ] اختبار صلاحيات كل دور على الخادم، بما في ذلك محاولات الوصول إلى موارد مؤسسة أخرى.
- [ ] مراجعة رفع الملفات، وحدود الحجم والنوع، وتخزين الملفات خارج مسارات الويب العامة.
- [ ] مراجعة التبعيات والإعدادات وفق متطلبات مخاطر التطبيق، باستخدام OWASP ASVS مرجعًا.

## البيانات والاستعادة

- [ ] التحقق من ترحيلات قاعدة البيانات ومصدرها وإمكانية تطبيقها على نسخة اختبار.
- [ ] تنفيذ نسخة احتياطية واستعادة فعلية إلى بيئة منفصلة.
- [ ] اختبار حذف/تصدير البيانات وصلاحيات سجل التدقيق.

## التشغيل والاعتمادية

- [ ] اختبار توقف الخدمة وانقطاع مزود API وانتهاء التفويض وحدود الاستخدام.
- [ ] لا توجد إعادة محاولة تلقائية لعملية نشر خارجية غير مؤكدة دون آلية idempotency أو فحص حالة.
- [ ] قياس زمن استجابة API ووقت تحميل الواجهة على أجهزة مستهدفة.
- [ ] تسجيل أخطاء من دون أسرار أو محتوى حساس، وإضافة تنبيهات مناسبة.
- [ ] اختبار بناء ونشر يمكن تكراره في بيئة نظيفة.

## تجربة المستخدم وإمكانية الوصول

- [ ] اختبار RTL وLTR على الكمبيوتر والتابلت والهاتف.
- [ ] اختبار الوضع الداكن والفاتح والتباين والتركيز بلوحة المفاتيح.
- [ ] اختبار حالات التحميل والفراغ والخطأ والنجاح.
- [ ] اختبار WCAG 2.2 حيث ينطبق، بما في ذلك التنقل بلوحة المفاتيح وتقليل الحركة.
- [ ] التأكد من أن كل زر يؤدي إجراءً حقيقيًا، وأن بيانات العرض ليست وهمية.

## التكاملات

- [ ] توثيق القدرات الفعلية والصلاحيات المطلوبة لكل مزود.
- [ ] اختبار الربط والإلغاء وتجديد التفويض والفشل وحدود API في بيئة اختبار المزود.
- [ ] عدم وصف أي منصة بأنها متصلة أو قادرة على النشر ما لم ينجح تحقق حقيقي.

## اعتمادات موفري الخدمة وOAuth — 0.16.0

- [ ] قبل استخدام `IntegrationCredential`، ولّد `PROVIDER_TOKEN_ENCRYPTION_KEY` بمفتاح Fernet عشوائي، واحفظه خارج مستودع المصدر في مدير أسرار/إعدادات تشغيل محمية. لا تعِد استخدام `SECRET_KEY`.
- [ ] طبّق/راجع migration `backend/migrations/postgresql/0160_integration_credentials.sql` على نسخة قاعدة بيانات مماثلة للإنتاج، وخذ نسخة احتياطية واختبر الاستعادة قبل الترحيل. هذا الملف ينشئ الجدول الجديد فقط؛ لا يحل محل migration baseline لقاعدة جديدة.
- [ ] لا ترسل رموز موفري الخدمة من المتصفح إلى أي endpoint. خدمة `credential_store` داخلية حتى يكتمل تدفق OAuth الخاص بكل موفر ويثبت هوية الحساب البعيد.
- [ ] خطّط لتدوير مفاتيح التشفير وإعادة تشفير البيانات قبل تغيير المفتاح؛ لا تبدل المفتاح عشوائيًا لأن ذلك يجعل ciphertext الحالي غير قابل للفك.
- [ ] لا تنشر Webhook حتى تتوفر endpoint تحدد حد حجم الجسم، وتتحقق من signature على البايتات الخام قبل JSON، وتختار السر الصحيح للمنتج، وتتعامل مع التكرار وإعادة الإرسال.
- [ ] لا تعتبر `scheduled_at` كافيًا للنشر التلقائي؛ يجب أن يوجد worker/queue دائم، وسياسة idempotency، ومصالحة للنتائج المجهولة قبل تفعيل النشر المجدول.

## جلسة واجهة المتصفح وخدمة التفويض المشتركة

- [ ] معالجة مخاطر تخزين رمز جلسة التطبيق في `sessionStorage` داخل `frontend/app.js`. قيّم انتقالًا مرحليًا إلى BFF/جلسة خادمية وملف ارتباط `HttpOnly; Secure; SameSite` مع حماية CSRF؛ لا تنفّذ هذا التغيير دون خطة توافق واختبارات للمصادقة والخروج وانتهاء الجلسة.
- [ ] توحيد تدفق Google الحالي الموجود في `backend/app/main.py` مع خدمة `backend/app/integrations/authorization.py` قبل إضافة مزود اجتماعي جديد، لتجنب وجود تنفيذين مختلفين لدورة state/PKCE/ربط المتصفح.
- [ ] تسجيل مراجعة تطبيقية وفق OWASP ASVS v5.0.0 وRFC 9700 وRFC 10017، مع تحديد المتطلبات المنطبقة وأدلة الاختبار؛ لا تعتبر الرجوع إلى المعايير دليل امتثال تلقائيًا.

## OAuth / التكاملات (0.16.0)

- [ ] تأكد من أن Google OIDC يبدأ من نفس الأصل الذي يستضيف الواجهة حتى يُحفظ ملف الربط المؤقت، وأن callback يستخدم HTTPS في الإنتاج.
- [ ] تحقق من خصائص ملف الارتباط: `HttpOnly`, `SameSite=Lax`, `Secure` في الإنتاج، ومسار callback فقط؛ لا تضع قيمة الربط في JavaScript أو السجلات.
- [ ] قبل إضافة موصل اجتماعي جديد، اختبر `state` المربوط بالمتصفح، PKCE S256، nonce عند OIDC، redirect URI مطابقًا تمامًا، واستعمال transaction لمرة واحدة.
- [ ] لا تفعّل موصل Meta أو Webhook أو عامل جدولة حتى تكون المسارات الفعلية، إدارة الأسرار، التوقيع/التحدي، إزالة تكرار الأحداث، والإعادة الآمنة مختبرة.
- [ ] جهّز `PROVIDER_TOKEN_ENCRYPTION_KEY` من مدير أسرار خارج قاعدة البيانات، وخطة آمنة للنسخ الاحتياطي والتدوير؛ لم يتم تطبيق تدوير مفاتيح آلي في 0.16.0.


## إضافات التحقق 0.17.0

- [ ] إجراء تدفق Google OIDC فعلي باستخدام إعدادات اختبار صحيحة وredirect URI مطابق، مع فحص log وعدم ظهور `state` أو `code` أو cookies أو الرموز.
- [ ] اختبار callback متزامن/مكرر على PostgreSQL: يجب أن تفوز معاملة واحدة فقط وتصل إلى token exchange.
- [ ] اختبار إعادة ربط Google identity بعد تعطيل العضوية أو تغيير `auth_version`.
- [ ] المحافظة على الفرق بين `identity_link` للمستخدم و`link` لحسابات النشر؛ لا توسّع صلاحيات الموصلات المستقبلية دون اختبار roles.


## قابلية التشخيص التشغيلي — 0.18.0

- [ ] تأكد من ظهور `X-Request-ID` في الاستجابات، و`Server-Timing` في طلبات API.
- [ ] راجع سجلات أخطاء 500 والطلبات التي تتجاوز 1500 مللي ثانية، وتأكد أنها لا تحتوي query strings أو رموز جلسات أو أجسام الطلبات.
- [ ] اربط معرف طلب من استجابة فعلية بسجل الخادم في بيئة التشغيل، ولا تعتبر ذلك نظام metrics أو tracing مركزيًا مكتملًا.
- [ ] قبل الإنتاج، حدد وجهة سجلات مناسبة، وسياسة احتفاظ، وصلاحيات وصول، وتنبيهات، مع منع الأسرار والبيانات الشخصية غير اللازمة من السجلات.
