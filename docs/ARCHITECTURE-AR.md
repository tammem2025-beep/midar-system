# البنية الحالية لمِدار وحدودها

## تحديث إصدار 0.16.0

يعتمد هذا التقرير على المصدر 0.16.0. أضيفت خدمة داخلية لمعاملات OAuth، وربط Google OIDC بملف ارتباط مؤقت مرتبط بالمتصفح، وعقد موصلات مستقلة، وتخزين Fernet لرموز موفري الخدمة، ودوال تحقق webhook. هذه أساسات جاهزة للاختبار وليست موصلات اجتماعية إضافية مفعلة.

## البنية المرصودة في المصدر الأصلي 0.14.0 وخط الأساس المستمر

- **واجهة المستخدم:** HTML وCSS وJavaScript دون إطار SPA منفصل، واتجاه افتراضي عربي RTL مع دعم إعدادات المظهر.
- **الخادم:** Python وFastAPI، ومسارات API معرفة في `backend/app/main.py`.
- **البيانات:** SQLAlchemy، مع SQLite للتشغيل المحلي وإمكانية إعداد PostgreSQL في بيئة Docker وفق الإعدادات الفعلية.
- **الهوية والأمان:** جلسات Bearer موقعة، وأدوار عضوية، ونطاق مؤسسة في عمليات البيانات. يحكم الخادم الوصول الفعلي؛ إخفاء عناصر الواجهة ليس حدًا أمنيًا.
- **الواجهة القابلة للتثبيت:** Service Worker وWeb App Manifest وملفات أيقونة.
- **التكاملات المتاحة:** كتالوج قدرات مستقل، وGoogle OIDC للهوية بعد الإعداد، وموصل Telegram محدود للنشر النصي اليدوي بعد التحقق من الوجهة. لا تعتبر بقية المنصات فعّالة لمجرد ظهور اسمها في الكتالوج.

## ما لا ينبغي افتراضه

- وجود ملفات إعداد في أرشيف المصدر لا يثبت أن الخدمة الخارجية أُعدت فعليًا.
- إدخال موعد منشور لا يعني أن عامل جدولة خلفي ينشره تلقائيًا.
- وجود شاشة محادثات محلية لا يعني اتصالها بصندوق وارد خارجي.
- نجاح اختبارات API لا يعادل اختبارًا مرئيًا لكل الصفحات، أو اختبار حمل، أو اختبار اختراق مستقل.

## اتجاه معماري موصى به

حافظ على **Modular Monolith** في المدى القريب، وأنشئ حدودًا واضحة داخل الحزمة: المصادقة، ومساحات العمل، والمحتوى، والوسائط، والموصلات، والتحليلات، والتدقيق. انقل المسارات إلى وحدات أصغر تدريجيًا مع المحافظة على عناوين API وعقود البيانات واختبارات الانحدار. لا تضف Redis أو Celery أو خدمات مصغرة إلا بعد تحديد احتياج تشغيلي وقياسه.

## فجوات ما قبل الإنتاج

- مراجعة أمنية مستقلة، ومراجعة مخاطر التخزين الحالي لرمز Bearer في `sessionStorage`، وضوابط XSS.
- تحديد معدل الطلبات، وHTTPS وإعدادات الإنتاج، وإدارة أسرار مُحكمة.
- التحقق من وجود ترحيلات قاعدة البيانات ومراجعتها وتشغيلها في بيئة منفصلة.
- اختبار استعادة النسخ الاحتياطية واختبارات حمل ومراقبة أخطاء فعلية.
- عمال خلفيون موثوقون وجدولة وإعادة محاولات آمنة عند تطوير النشر المجدول.
- تكامل رسمي ومختبر لكل منصة قبل الادعاء بدعم النشر أو الرسائل أو التحليلات.

## طبقة التكاملات والأمن — 0.16.0

- `integrations/contracts.py` يحدد capability contract، و`integrations/registry.py` هو سجل التنفيذ الفعلي، وهو مستقل عن كتالوج الواجهات. Telegram وحده يدعم التحقق من الوجهة والنص؛ غير ذلك لا يُسجّل كمُوصل حي.
- `integrations/authorization.py` يوفر معاملات OAuth قصيرة العمر ذات state مخزن بالـ hash وnonce وPKCE S256، ورمز ربط متصفح. أما مسارات Google OIDC الحالية فتستخدم `ProviderOAuthBinding` لتخزين hash الربط وترسل cookie مؤقتًا `HttpOnly; SameSite=Lax` (و`Secure` بالإنتاج/HTTPS)، وترفض callback من متصفح غير المتصفح الذي بدأ التدفق. يعيد helper العام التحقق من عضوية المالك/المدير وإصدار المصادقة قبل استهلاك state؛ ولا ينشئ وحده تدفق OAuth لمنصة خارجية.
- `security_tokens.py` يوفر تشفير Fernet لاستخدامه داخل الخادم فقط، باستخدام مفتاح منفصل `PROVIDER_TOKEN_ENCRYPTION_KEY` ورفض fail-closed عند غيابه.
- `models.IntegrationCredential` و`integrations/credential_store.py` يضيفان أساسًا لحفظ access/refresh tokens كـ ciphertext مربوطًا بالمؤسسة والحساب. لا توجد API عامة لقراءة هذه الرموز ولا تكامل OAuth اجتماعي متصل به بعد.
- `integrations/webhook_security.py` يحتوي تحقق HMAC-SHA256 لرسائل Meta ورمز Telegram secret header. لا توجد Webhook endpoints فعّالة بعد؛ لا يعتبر وجود الدوال دعمًا للرسائل الواردة.
- في وضع development/test، `prepare_local_schema()` ينشئ الجدول الجديد عبر SQLAlchemy. قواعد الإنتاج يجب أن تطبق migration مناسبًا بعد النسخ الاحتياطي ومراجعة توافق المخطط؛ انظر `backend/migrations/`.


## تحديث 0.17.0 — خدمة التفويض المشتركة

تدفق Google OIDC يستخدم الآن خدمة `integrations/authorization.py` لإصدار معاملات قصيرة العمر تتحقق من `state` المموّه، وربط المتصفح، و`nonce`، وPKCE S256. يُستهلك سجل المعاملة بحذف SQL شرطي ذري، ثم يُحفظ هذا الاستهلاك قبل طلب شبكة المزود لمنع إعادة استخدام callback.

تميّز الخدمة بين `identity_link` (ربط هوية دخول خارجية بحساب المستخدم نفسه) و`link` (ربط حساب مزود للنشر ويتطلب owner/admin). لا يعني هذا وجود OAuth اجتماعي مكتمل؛ تبادل رموز Meta وWebhooks والعمال الخلفية ما زالت خارج نطاق الإصدار.


## تحديث 0.18.0 — قابلية التشخيص دون تسريب بيانات

تضيف طبقة HTTP معرّفًا عشوائيًا يُنشأ على الخادم لكل طلب ويُعاد في `X-Request-ID`. لطلبات API يُضاف `Server-Timing: app;dur=...` لقياس زمن معالجة التطبيق. تُسجل الاستثناءات غير المعالجة والطلبات التي تجاوزت 1500 مللي ثانية مع الطريقة وقالب المسار المعروف دون query string أو جسم الطلب أو الرؤوس؛ ويستعمل عنصر نائب للطلبات غير المطابقة لتجنب تسجيل مسار خام محتمل الحساسية. لا تُسجل رسالة الاستثناء نفسها؛ يقتصر سجل الاستثناء على النوع ومواقع إطارات المكدس، ويرجع العميل رسالة 500 عامة مع معرّف الطلب. لا يحل ذلك محل نظام metrics/tracing خارجي؛ إنه أساس تشخيص محلي قابل للربط والاختبار.
