# تقرير التدقيق الهندسي والبصري — مِدار 0.19.0

**تاريخ المراجعة:** 24 أكتوبر 2026  
**نطاق التنفيذ:** الدفعة الأولى من إعادة هندسة نظام التصميم، المساحات والطبقات المشتركة، وتطبيق المظهر.  
**قاعدة التحديث:** المصدر 0.18.0، والترقية المقصودة إلى 0.19.0.  
**نوع الدليل:** مراجعة المصدر + اختبارات آلية + فحص CSS + متصفح Chromium على قالب بصري ممثل. ليست جلسة مصادقة حقيقية، ولا اختبارًا على جهاز Windows الخاص بالمستخدم، ولا شهادة امتثال.

## 1. الملخص التنفيذي

عُثر على نمط تصميم موزّع على 13 وحدة CSS مصدرية قبل هذا التغيير، مع ملف تشغيل مجمّع `frontend/midar-ui.css`، وتعريفات مظهر في `frontend/settings-enhanced.js`. كان ترتيب الطبقات المتراكمة يسمح ببقاء بعض الألوان والحدود والخلفيات في وحدات الميزات أقل ارتباطًا بنظام اللون المركزي. كذلك اختلفت قيم ارتفاع الشريط العلوي بحسب قواعد متراكمة، وكان الوصف في الشريط العلوي يكرر جزءًا من سياق العنوان الذي يظهر في منطقة المحتوى.

أُضيفت وحدة `13-design-system.css` بوصفها الطبقة النهائية، وأصبح عدد وحدات المصدر **14 وحدة**. تتضمن طبقة رموزًا دلالية للوضعين الفاتح والداكن، وست لوحات accent، وجسر توافق مع عدد من متغيرات CSS القديمة، وقواعد موحدة للمكونات المشتركة. بقيت البنية التقنية الحالية كما هي؛ لم يُعَد بناء التطبيق من الصفر ولم تتغير قاعدة البيانات أو منطق المصادقة والصلاحيات عمدًا.

## 3. الملفات التي تغيّرت

- `frontend/styles-src/13-design-system.css` — إضافة طبقة الرموز الدلالية وقواعد shell والمكونات والوضع الفاتح والاستجابة.
- `tools/build_frontend_css.py` — إضافة الوحدة الأخيرة وترقيم bundle تلقائيًا من `VERSION`.
- `frontend/midar-ui.css` — إعادة بناء الملف المجمّع من وحدات المصدر.
- `frontend/index.html` — تحديث مراجع الأصول إلى 0.19.0، وتوحيد زر القائمة إلى SVG مضمّن.
- `frontend/settings-enhanced.js` — تحديث لون theme-color الوصفي ليتوافق مع الوضع الحالي.
- `frontend/app.js`, `frontend/sw.js` — تحديث كسر التخزين المؤقت واسم cache الخاص بالـ PWA.
- `backend/app/main.py` — تحديث إصدار تطبيق API إلى 0.19.0 فقط.
- `VERSION`, `README.md`, `CHANGELOG-0.19.0.md` — مرجع الإصدار والتوثيق.
- `tests/test_api.py`, `tests/test_visual_design_system.py` — تحديث مراجع الإصدار وإضافة اختبارات عقد التصميم.

لم يُضمّن أو يُعدّل `.env` أو أي ملف قاعدة بيانات في حزمة التحديث. لم يتغير مخطط قاعدة البيانات أو عقد endpoints الخاص بالأعمال عن قصد.

## 4. نظام التصميم المركزي

تعرّف الوحدة الجديدة متغيرات للألوان الدلالية، منها:

- الخلفية العامة: `--md-page` و`--md-page-glow`.
- الأسطح: `--md-surface`, `--md-surface-raised`, `--md-surface-soft`, `--md-surface-hover`.
- النصوص: `--md-text`, `--md-text-muted`, `--md-text-soft`.
- الحدود والظلال: `--md-border`, `--md-border-strong`, `--md-shadow-*`.
- الإجراء واللون الأساسي: `--md-accent`, `--md-action`, `--md-action-2`, `--md-focus`.
- المسافات والأبعاد: `--md-space-*`, `--md-control-height`, `--md-radius-*`.

اللوحات المتاحة هي violet وblue وcyan وemerald وrose وamber. تتبعها مكونات الإجراءات والتركيز والحالات النشطة. تبقى ألوان النجاح والتحذير والخطأ مستقلة حتى لا يؤدي تغيير لون العلامة إلى تغيير معنى حالة نظامية.

تستعمل طبقة الرموز aliases لعدد من متغيرات النظام القديم، لتقليل خطر كسر ميزات موجودة. ومع ذلك، لا يزال بعض CSS القديم يحتوي ألوانًا ثابتة، خاصة في زخارف أو شاشات متخصصة؛ هذا الإصدار **لا يدّعي تحويل كل declaration لوني في المشروع إلى token**. توصى مراجعة تدريجية لكل شاشة مع لقطات ومقارنة مرئية بدل استبدالات نصية عمياء.

### فحص Chromium على قالب بصري ممثل

استُخدم ملف `frontend/index.html` مع CSS مضمّن، وتعطيل JavaScript الحقيقي، واستبدال محتوى الصفحة بمحتوى static fixture. لذلك هو فحص لهيكل CSS والمساحات والثيم، وليس اختبار E2E للمصادقة أو البيانات الحقيقية.

- المقاسات: 1440×1050، 1024×900، 768×900، 390×844، 320×740.
- الوضعان: الداكن والفاتح.
- قياس `document.documentElement.scrollWidth` و`document.body.scrollWidth` طابق عرض viewport في المقاسات الخمسة، من دون overflow أفقي في fixture.
- ارتفاع الشريط: 64px على 1440، و60px على مقاسات الهاتف.
- تم التحقق من أن لوحات الألوان الست تؤدي إلى ست قيم متميزة لمتغير اللون الأساسي في كلا الوضعين (12 حالة theme/accent).
- أُخذت صور desk­top وmobile للاستخدام كمرجع مرئي. لا تمثل الصور كل صفحات التطبيق.

## 7. حدود التصريح

لم يُشغّل المثبّت على Windows حقيقي في بيئة العمل، ولم تُجرَ جلسة دخول حية بالمنصة، ولا اختبار اختراق خارجي، ولا قياس أداء عبر شبكة، ولا فحص آلي كامل لـ WCAG 2.2 AA. هذه الدفعة **تحسن اتساق التصميم وتثبت مجموعة من العقود التقنية**، لكنها ليست شهادة منافسة عالمية ولا شهادة امتثال. يجب التحقق من التطبيق الفعلي بعد تثبيت التحديث.

## 8. معيار قبول هذه الدفعة

تعتبر هذه الدفعة جاهزة للاختبار المحلي عندما تكون ملفاتها مطابقة للـ SHA-256 في حزمة التحديث، ويعاد بناء CSS ببصمة ثابتة، وتنجح اختبارات Python وJavaScript، ويعمل التطبيق محليًا من دون تغيير البيانات. إذا فشل الاختبار بعد التثبيت، يجب أن يتوقف المثبّت عن إعلان النجاح ويستعيد الملفات التي غيّرها فقط.
