## البنية المرصودة

- واجهة HTML/CSS/JavaScript مع PWA. ملف `frontend/app.js` حجمه نحو 125 KB؛ نظام CSS يتكون من 13 وحدة مصدرية وملف تشغيل مجمع.
- Backend: Python/FastAPI، مع SQLAlchemy وSQLite محليًا وإمكانية إعداد PostgreSQL.
- المصادقة: Bearer JWT مع إبطال عبر `auth_version`، عضوية ومساحة عمل، أدوار وصلاحيات على الخادم، وحدود محاولات دخول.
- Google OIDC: state وPKCE S256 وnonce وربط متصفح واستهلاك معاملة لمرة واحدة ضمن خدمة OAuth المشتركة.
- تخزين رموز مزودي الخدمة: خدمة داخلية تستخدم Fernet ومفتاحًا منفصلًا. Telegram موصل محدود؛ الكتالوج لا يعني أن باقي المنصات موصولة.
- لا توجد في المصدر الحالي endpoints فعالة لـ Webhooks الاجتماعية، ولا Queue/Worker/Scheduler دائم للنشر التلقائي. دوال التحقق من توقيع Webhook وحدها لا تمثل استقبالًا فعليًا للأحداث.

## التغيير المحدود المنفذ في 0.18.0

- كل استجابة تحمل `X-Request-ID` عشوائيًا من الخادم. لا يُعتمد معرّف يرسله العميل.
- استجابات `/api/` تحمل `Server-Timing: app;dur=...`، وهو وقت المعالجة داخل التطبيق وليس زمن الشبكة أو الطرف الثالث الكامل.
- تسجل أخطاء 5xx والطلبات التي تتجاوز 1500 ms بمعرّف الطلب والطريقة وقالب route المعروف والحالة والمدة. لا يُسجل المسار الخام للطلبات غير المطابقة؛ يُستخدم `<unmatched-route>`. يتم استبعاد query strings وheaders وbody.
- الاستثناءات غير المعالجة ترجع 500 عامة مع معرّف الطلب. تسجل log نوع الاستثناء ومواقع إطارات المكدس فقط، لا رسالة الاستثناء التي قد تحتوي بيانات حساسة.
- أضيفت اختبارات للتحقق من تفرد المعرّف، ووجود Server-Timing، وعدم تسرب query token أو نص الاستثناء، وربط 500 بمعرّف الطلب.
- لم تُضف مكتبات، ولم يتغير مخطط قاعدة البيانات أو `.env` أو منطق مصادقة/صلاحيات الأعمال.
