# قابلية تشخيص الطلبات — مِدار 0.18.0

## ما الذي توفره الطبقة؟

- ينشئ الخادم معرفًا عشوائيًا من 32 خانة hex لكل استجابة ويرسله في `X-Request-ID`. لا يتم اعتماد قيمة معرّف يرسلها العميل.
- يضيف `Server-Timing: app;dur=...` إلى استجابات `/api/` لعرض زمن معالجة التطبيق، وليس زمن الشبكة الكامل أو زمن الطرف الثالث وحده.
- يسجل حالات 5xx والطلبات التي تتجاوز 1500 ملي ثانية بصيغة key-value تشمل المعرّف والطريقة والمسار والحالة والمدة.
- عند استثناء غير معالج، يسجل نوع الاستثناء ومواقع إطارات المكدس دون رسالة الاستثناء أو query string أو headers أو body، ويعيد استجابة 500 عامة تتضمن المعرّف.
- يسجل قالب المسار المعروف فقط؛ وللطلبات غير المطابقة يُستخدم `<unmatched-route>` بدل المسار الخام، لتجنب تسرب معرّفات أو أسرار قد تظهر داخل مسار مخصص. ويُستبعد query string عمدًا لأن OAuth codes وtokens قد تظهر فيه. لا تُسجل عناوين Authorization أو cookies أو محتويات النماذج.

## كيف يستخدمه الدعم؟

عند ظهور خطأ داخلي، يطلب فريق الدعم قيمة `X-Request-ID` من أدوات المطور/تبويب Network أو من JSON لخطأ 500، ثم يبحث بها في سجل الخادم. لا يحتاج المستخدم إلى مشاركة رمز الجلسة أو الطلب كاملًا.

## الحدود

هذه طبقة تشخيص محلية، وليست نظام metrics أو distributed tracing، ولا تجمع زمن SQL لكل استعلام، ولا ترسل تنبيهات ولا تحدد تلقائيًا المستخدم أو المؤسسة. قبل الإنتاج، ينبغي توصيل سجلات `midar.request` بوجهة سجلات ذات تحكم وصول واحتفاظ مناسبين، وتجنب تسجيل معلومات شخصية غير لازمة.
