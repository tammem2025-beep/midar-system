# M — Digital Business Management

منصة لإدارة الأعمال الرقمية والمحتوى الاجتماعي. إصدار المصدر الحالي: **0.20.0**. الاسم التجاري والهوية الحالية: **M — Digital Business Management**.

## دليل البدء السريع

ابدأ بقراءة `START-HERE-AR.md` للحصول على خطوات التحديث الآمن وملاحظات الهوية والاختبارات. على Windows يوجد المشغل الرسمي `run-m-windows.ps1` مع الاحتفاظ بالاسم القديم `run-midar-windows.ps1` كاختصار متوافق.

## التشغيل المحلي

1. أنشئ بيئة Python افتراضية.
2. ثبّت الاعتمادات: `python -m pip install -r backend/requirements.txt`
3. جهّز `.env` من `.env.example` بقيمة `SECRET_KEY` عشوائية؛ لا تشارك `.env` أو رموز منصات.
4. شغّل التطبيق من الأداة المعتادة أو عبر `uvicorn app.main:app` من مجلد `backend` حسب إعداد المشروع.
5. الاختبارات: `python -m pytest -q` من جذر المشروع.

## حدود التكاملات الحالية

- Google OIDC مخصص لهوية مستخدم M، وليس تفويضًا لإدارة حسابات التواصل.
- Telegram موصل جزئي: التحقق من وجهة بوت ونشر نص بعد الإعداد والتفعيل الصريح.
- Meta/Instagram/WhatsApp/X وغيرها لا تُعد متصلة أو قابلة للنشر لمجرد ظهورها في الكتالوج.
- 0.16.0 أضاف أساس الموصلات وتخزين الرموز المشفر والتحقق من توقيعات Webhook.
- 0.17.0 جعل Google OIDC يستخدم خدمة معاملات OAuth المشتركة بدل ازدواج منطق state/PKCE/ربط المتصفح، وأضاف استهلاكًا ذريًا لمعاملة التفويض وتنظيفًا صريحًا للحالات المنتهية. لا توجد بعد تدفقات OAuth اجتماعية لمنصات Meta أو Webhook endpoints أو عامل نشر مجدول فعّال.

راجع `docs/ENGINEERING-AUDIT-0.20.0-AR.md` لتقرير هذه الدفعة، و`docs/INTEGRATION-SECURITY-AUDIT-AR.md` و`docs/PRODUCTION-CHECKLIST.md` قبل نشر النظام.

## 0.20.0 — هوية M ونظام العلامة

- اعتماد الاسم التجاري M والوصف الرسمي Digital Business Management والشعار Manage. Connect. Grow.
- إضافة شعار M المتجهي وقفل الشعار العرضي وأيقونات PWA المحدثة.
- توحيد الاسم الظاهر وعناوين الصفحات والبيانات الوصفية وملف manifest ورسائل المنتج الحالية.
- إضافة طبقة CSS مركزية جديدة لهوية M، ولوحة سياني/أزرق/بنفسجي، وضبط المساحات والرأس والقائمة والمكونات المتكررة.
- جعل اللون الأساسي الافتراضي للمستخدمين الجدد أزرق العلامة، مع الحفاظ على إعدادات المستخدمين الحاليين المخزنة.
- تحديث الإصدار والـ cache busting والاختبارات والتوثيق.
- الاحتفاظ بمسار `midar-ui.css` وبمفاتيح الجلسة الداخلية القديمة مؤقتًا لتجنب كسر الإشارات أو إخراج الجلسات الحالية؛ الاسم القديم لا يظهر كهوية في الواجهة.

## 0.19.0 — نظام التصميم البصري المركزي

- توحيد متغيرات الألوان والأسطح والنصوص والحدود والتباعد تحت طبقة دلالية واحدة.
- ربط لوحات الألوان الست بألوان الإجراءات والتركيز والتنقل والمكونات المتكررة مع الحفاظ على دلالات النجاح والتحذير والخطأ.
- ضبط ارتفاع الشريط العلوي إلى 64px على سطح المكتب و60px كحد أدنى على الهاتف، وتقليل تكرار العنوان الوصفي.
- تحسين اتساق النماذج والجداول والبطاقات والنوافذ ومكونات لوحة التحكم والتقويم مع الوضع الفاتح.
- إضافة اختبار آلي لعقد نظام التصميم وتحديث أصول PWA وإصدار API إلى 0.19.0.

## 0.18.0 — قابلية التشخيص التشغيلي

- يضيف معرّف طلب عشوائيًا في `X-Request-ID` لكل استجابة، ووقت معالجة API في `Server-Timing`.
- يسجل استثناءات الخادم والطلبات البطيئة فقط، مع استبعاد query strings والرؤوس وأجسام الطلبات من سجل المراقبة، واستخدام عنصر نائب بدل المسار الخام للطلبات غير المطابقة.
- يحجب تفاصيل الاستثناء عن العميل، ويعيد معرّف الطلب لتمكين تتبع الخطأ دون كشف رسالة داخلية.
- لا يضيف مكتبات أو يغيّر قاعدة البيانات أو عقد API للأعمال.
