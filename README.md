# M

**Manage. Connect. Grow.**

منصة لإدارة الأعمال الرقمية والمحتوى والتواصل. الإصدار الحالي: **0.21.1**.

## البدء على Windows

1. احتفظ بنسخة احتياطية من قاعدة البيانات وملف `.env`.
2. استخدم Python 3.12 أو 3.13.
3. أنشئ البيئة الافتراضية من جذر المستودع:

   ```powershell
   py -3.13 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
   Copy-Item .env.example .env
   ```

4. عيّن قيمة عشوائية خاصة بك لـ `SECRET_KEY` داخل `.env`. لا ترفع هذا الملف إلى GitHub ولا تشارك الرموز السرية.
5. شغّل `run-m-windows.ps1` من جذر المشروع. يجهّز المشغّل الإعدادات المحلية ويبدأ الخادم على `http://127.0.0.1:8000`.

## التشغيل والاختبارات

- أعد بناء CSS بعد تحرير وحدات المصدر: `python tools/build_frontend_css.py`.
- اختبارات API والنظام: `python -m pytest -q`.
- فحص صياغة JavaScript: `node --check frontend/app.js`، `node --check frontend/settings-enhanced.js`، `node --check frontend/command-center.js`.
- ملف `frontend/midar-ui.css` ملف مجمّع؛ عدّل `frontend/styles-src/` ولا تعدّل الملف المجمّع يدويًا.

## وظائف المنتج الحالية

تتضمن المنصة لوحة تحكم، وإدارة مسودات المنشورات وتقويم المحتوى، والحملات، ومكتبة الوسائط، والعملاء، والمهام، والفريق والصلاحيات، والتفضيلات وسجل النشاط، ومسار هوية Google OIDC عند إعداد بيانات OAuth.

## حدود تكاملات التواصل

إظهار منصة في الكتالوج لا يعني أنها متصلة. Google OIDC لتسجيل الدخول إلى M وليس تفويضًا للنشر الاجتماعي. الموصل الحالي لـ Telegram محدود بالتحقق من الوجهة والنشر النصي بعد ضبط الإعدادات والتفعيل الصريح. تدفقات OAuth/Webhooks والنشر المجدول للمنصات الأخرى يجب تنفيذها واختبارها واعتمادها لكل مزود قبل عرضها كوظائف جاهزة.

راجع `docs/INTEGRATION-SECURITY-AUDIT-AR.md` و`docs/PRODUCTION-CHECKLIST.md` قبل أي نشر عام، و`docs/BRAND-IDENTITY-M-0.21.0-AR.md` لمواصفات الهوية.

## أمان البيانات

لا تضع `.env`، أو قواعد بيانات المستخدمين، أو رموز المنصات في المستودع. قبل التحديث، أوقف الخادم وخذ نسخة احتياطية. لا تحذف قواعد البيانات أو النسخ القديمة إلا بعد التحقق من أن البيانات والحسابات تظهر في النسخة الحالية.
